# Villa Web 性能验收

引擎分支合并和渲染、调度、输入变更交付前，用上一个已验收包与本次正式包做同场景对照。记录两个仓库的提交及包的哈希。报告注明恢复按钮、视角、分辨率模式和启动参数，方便用同样的页面复现。

## 测试条件

- 使用用户反馈涉及的浏览器、正式页面、物理输出分辨率和 DPR。记录内部渲染分辨率、抗锯齿、Lumen、VSM、VT、Nanite 实际状态和 PSO 就绪状态。两组设置不同，先记录差异并说明对照的范围。
- 两版用同一台机器、同一显示器刷新率、同一个浏览器版本和同一前后台状态。测前记录 GPU 显存占用、GPU/CPU 负载与电源状态。一次只运行一个测试场景。若有录屏、采集器、受限 CPU 亲和性或远程桌面，记录条件并检查是否影响结果。
- 使用 `A → B → B → A` 交叉顺序，各跑两次。浏览器缓存条件需对等，同一轮按正式页面正常等待加载完成后再开始。剔除整轮时记录原因和重跑结果，保存首次走动中的所有长帧。
- 体感抖动与平均 FPS 差距不符时，加 `--page-pacing` 同时采集页面回调和页面观察到的画面更新，分别列出 P95/P99。交换两份持久浏览器配置再跑客厅单独转向，检查差异跟随包还是浏览器配置。诊断开关先核对运行时计数，再开始采样。

## 必测场景

| 场景 | 操作与确认 |
| --- | --- |
| 客厅静止 | 从沙发、挑高吊灯和二楼栏杆可见的起点记录基础帧节奏，回读玩家位置确认没有偏移。 |
| 客厅首次同时移动和转向 | 从客厅起点在客厅和相连开阔区用 WASD 大范围移动，同时左右扫视并改变俯仰。确认最远玩家位移至少 3 米，累计玩家位移至少 7 米，并保留相机偏航和俯仰轨迹。 |
| 客厅重复同时移动和转向 | 回到同一客厅起点并重复相同输入。在同一轮中分别保留首次和重复采样。 |
| 客厅单独转向 | 在同一起点站定，连续转向并快速反向扫视，回读角度并确认玩家未移动。 |
| 客厅单独移动 | 在同一起点保持朝向，做大范围横移，回读位置和角度。 |
| 人工画面对照 | 在两版正式页面从相同客厅视角用实际键鼠大范围移动和转向。扫过沙发、楼上栏杆及餐厨交界，观察停顿、跳步和画面抖动。记录触发路段、方向、浏览器和时间点，必要时另做诊断录屏。用户反馈出现在外层比较页或自适应模式时，用相同入口和模式复现。 |
| 运动中清晰度 | 核对两版启动日志中实际生效的 `r.MotionBlurQuality`、TSR 和内外部分辨率。在同速同向转动时截取窗框、栏杆或餐椅边缘，对照拖影长度。另保存停止后的画面。即使帧率相当，也要单独记录清晰度结论。 |

相机脚本巡游可用于等轨迹渲染对照。键鼠探针的实际位姿随碰撞和输入时序变化，需比对相机轨迹和采样窗口，明显不同的路线要调整后重跑。浏览器自动化输入通过页面键鼠链路，物理鼠标、指针锁和显示体验由人工画面对照覆盖。出生点采样只用于基础回归。此前出生点键鼠测试实测移动半径约 1.4 米，客厅性能须以客厅测试为准。

## 采集入口

在本地预览服务启动、Node 可解析仓库使用的 Playwright 后执行。替换两个包目录和 `tag`，按目标浏览器选择 `chrome` 或 `msedge`。

```powershell
node tests/web-platform/probe-nanite-off-regression.cjs --interactive --interactive-route=living --headed --browser=chrome --modes=legacy,candidate,candidate,legacy --baseline-folder=villa-pso-eager-20261117-d/release --folder=villa-nanite-merged-20261118-raw-mouse --width=1920 --height=1080 --seconds=24 --tag=villa-living-abba
```

报告在 `tests/web-platform/results/<tag>/report.json`，包含各段原始提交时间戳、实际玩家和相机轨迹、设置与焦点。客厅起点截图保存在同一目录。各段分别报告平均 FPS、1% Low、P95/P99、最长帧和超过 33.3、50、100 ms 的帧数。1% Low 是最慢 1% 帧间隔平均值的倒数。比较长帧应同时看计数与每分钟频率。提交帧时间用于定位引擎节奏。显示卡顿以实际画面对照为准，必要时补录屏或呈现诊断。性能采样段关掉浏览器 trace、profiler 和额外 GPU 时间戳。

加 `--capture-turn` 可在性能采样结束后，从客厅起点水平匀速扫视并保存连续 PNG。`run.movingImages` 记录每张图采集前后的实际偏航、帧号和时间。选取朝向接近、同一物体可见的画面对照。用 `--motion-blur=shipped,shipped,shipped,shipped` 同时保留四轮各自的引擎配置日志。

对比打包前后，核对报告中的实际 `clock.mode`、`inputMode` 和启动 PSO 状态。测试保留原项目设置的正式包时，同时核对 `projectSettingsPreserved`、配置哈希和 `optimization-contract.json` 中的运行时配置。怀疑调度回归时，用同一个包在前台只切换帧时钟。下列操作保留原包的输入路径、WASM、Cook、INI 和 PSO 缓存。

```powershell
node tests/web-platform/probe-nanite-off-regression.cjs --interactive --interactive-route=living --headed --browser=chrome --modes=candidate,candidate,candidate,candidate --folder=villa-nanite-merged-20261118-raw-mouse --game-frame-clocks=owner,page,page,owner --width=1920 --height=1080 --seconds=24 --tag=villa-living-clock-abba
```

## 合并后显存排查

从两个仓库各自的合并第一父提交比较新增的每帧路径。核对当前场景中实际分配的资源、流送更新和 GPU 命令，在同一条客厅移动路线比较每帧数据。浏览器和页面 DPR 取人工反馈的实际值。

```powershell
node tests/web-platform/probe-nanite-off-regression.cjs --interactive --interactive-route=living --interactive-phases=walk-turn-first --headed --browser=msedge --dpr=1.5 --width=1920 --height=1080 --seconds=24 --gpu-transfers --modes=legacy,candidate,candidate,legacy --baseline-folder=villa-pso-eager-20261117-d/release --folder=villa-nanite-merged-20261118-raw-mouse --tag=villa-living-gpu-transfers
```

逐轮核对 `naniteIdleBefore/After` 的页池、代理数、更新数和暂存字节。`allocation.groups` 按名称、格式汇总仍可达的 GPU 资源描述符。`transfers` 记录显式复制、上传、清零和映射请求。用 `phase.frames.length` 归一化，未知格式参看 `unknownSize`。`atlasDispatch` 记录计算任务绑定全局距离场图集时的布局权限。实际字节访问、缓存命中及硬件带宽需另行测量。性能验收使用关闭 `--gpu-transfers` 的采样。

要验证距离场图集本身，以上命令去掉 `--gpu-transfers`，改用四个 `candidate`，增加 `--atlas-formats=r8unorm,r32float,r32float,r8unorm`，换一个 `--tag`。两组共用合并包的量化逻辑，启动时按实验格式创建图集和相应的 WebGPU 存储绑定。检查 `run.atlas` 的实际格式和尺寸、预缓存失败数、截图和五段帧节奏。该选项仅用于诊断。要单独检查常规 clipmap 更新，将格式参数换成 `--distance-field-updates=1,0,0,1`，核对引擎启动日志中的实际值。

## 交付判断

- 逐段比较两组数据，保留每轮数字。平均 FPS、1% Low、长帧和可见抖动分别判断。两轮方向不一致、目标画面抖动无法解释或任一必测项缺失时，将该项标为待验收并写清缺口。
- 探针 `pass` 代表采样与输入检查成功。实际性能结论要结合分段数据和人工观察，报告须附原始路径、呈现体验和未验收项。比较的是两个发布包时，将渲染路径归因留到同包单开关对照。
